# Видимая папка с глобальными настройками (`claude-config`)

> Инструкция одинаковая для Windows, macOS и Linux: агент сам определяет систему и
> подбирает способ.

**Когда:** первым делом на занятии 3, до темы MCP. К этому моменту в глобальном
`CLAUDE.md` уже что-то есть (промпт `personal-system-prompt.md`, занятие 2). Если нет,
не страшно: промпт сработает и так.
**Что делает:** переносит глобальный конфиг Claude Code из скрытой системной папки
(`~/.claude/` на macOS и Linux, `%USERPROFILE%\.claude` на Windows) в обычную видимую папку
`claude-config` внутри твоей папки `work`, рядом с проектами. На старом месте остаются
ссылки (симлинки). Claude Code работает ровно как раньше, а тебе удобно самому доливать
туда правила, скиллы и всё остальное.
**Как использовать:** в VS Code открыта папка `work`, отправь промпт ниже как есть. Если
агент спросит, где твоя рабочая папка, ответь полным путём: это нормальный ход, а не сбой.

> Зачем это нужно. `~/.claude/` это служебная папка: Claude Code всегда читает конфиг
> оттуда, и переименовать её нельзя. Но внутри лежат обычные текстовые файлы, поэтому их
> можно хранить в видимом месте, а в `~/.claude/` оставить только ссылки. Агент разницы не
> заметит, а папка будет на виду: зашёл и добавил новое.

```text
Хочу вынести свой глобальный конфиг Claude Code из скрытой системной папки в обычную
видимую папку claude-config. Она должна лежать в моей рабочей папке work, рядом с моими
проектами, а не в домашней папке и не в корне диска.

Работай только по полным (абсолютным) путям и на каждом шаге показывай, что получилось.

Сделай так:

1. Определи мою операционную систему.

2. Найди мою рабочую папку work, в которой лежат мои проекты (Persona и другие).
   Скорее всего VS Code открыт прямо в ней. Если нет, поищи в домашней папке каталог
   work или Work (регистр не важен). Нашёл ровно одну подходящую: назови её полный путь
   и продолжай. Не нашёл, кандидатов несколько или сомневаешься: ОСТАНОВИСЬ и спроси меня.
   Путь не выдумывай и папку наугад не создавай.

3. Проверь, не создавалась ли папка claude-config раньше где-то ещё: в домашней папке,
   внутри проекта или в корне диска. Если нашлась не в рабочей папке, перенеси её целиком
   в рабочую папку и перепроверь ссылки в системной папке конфига: те, что указывают на
   старое место, перезапиши (ссылка на исчезнувшую папку ломается молча).

4. Если папки claude-config в рабочей папке всё ещё нет, создай её там.

5. Найди системную папку конфига Claude Code (~/.claude на macOS/Linux,
   %USERPROFILE%\.claude на Windows) и разберись с ФАЙЛАМИ CLAUDE.md и settings.json:
   если файл существует и ещё НЕ является символической ссылкой, перенеси его в
   claude-config под тем же именем, а на старом месте создай символическую ссылку на новое
   расположение. Если файла нет, пропусти, пустышки не создавай.

6. Отдельно разберись с ПАПКАМИ rules, skills, commands, agents. Они нужны мне в любом
   случае, чтобы я сам складывал туда файлы:
   - если папки нет ни в системной папке конфига, ни в claude-config, создай её пустой
     внутри claude-config;
   - если папка есть в системной папке конфига и это не символическая ссылка, перенеси
     её в claude-config вместе с содержимым;
   - в системной папке конфига на месте каждой из этих папок в итоге должна стоять
     символическая ссылка на папку внутри claude-config;
   - в каждую папку, которую ты создал пустой, положи пустой файл .gitkeep, иначе пустая
     папка не попадёт в репозиторий, когда я буду делать бэкап на GitHub.

7. На macOS и Linux используй ln -s. На Windows создание ссылок требует включённого
   Режима разработчика или прав администратора. Упрёшься в ошибку доступа: не обходи её
   скрытыми способами, а объясни простыми словами, что происходит, и скажи включить Режим
   разработчика так: Win+R, вставить ms-settings:developers, Enter, включить переключатель
   «Режим разработчика», потом перезапустить VS Code. Если в терминале у меня открылся
   PowerShell, работай через cmd.

8. Ничего не удаляй безвозвратно. Сомневаешься: лучше скопируй, а не двигай.

9. В конце покажи:
   - полный путь к claude-config и что внутри;
   - содержимое системной папки конфига и куда ведёт каждая ссылка;
   - отдельно подтверди, что ни одна ссылка не «висит», то есть каждая ведёт на реально
     существующий файл или папку.
```

**Проверь себя:** открой новую сессию и спроси «как меня зовут?». Агент отвечает так же,
как раньше, значит глобальный `CLAUDE.md` читается через ссылку и всё работает.

**Что внутри `claude-config`:**

| Что | Зачем |
|---|---|
| `CLAUDE.md` | Кто ты и как с тобой говорить. Действует во всех проектах |
| `rules/` | Правила по темам. Первое положим следующим промптом |
| `settings.json` | Настройки и разрешения агента (если уже появился) |
| `skills/` | Навыки агента, наполним на занятии 4 |
| `commands/`, `agents/` | Свои команды и помощники, позже по курсу |

`CLAUDE.md` в папке проекта действует на один проект, этот на все сразу.

Следом: [`rules-nonconformism.md`](rules-nonconformism.md), первое правило в эту папку.

## Если агент не справился: ссылки руками

Агент справляется почти всегда, но на Windows изредка не хватает прав даже после Режима
разработчика (корпоративный ноутбук, групповые политики). Тогда вручную.

> В примерах ниже рабочая папка лежит в домашней и называется `work`. Если у тебя иначе,
> подставь свой путь.

<details>
<summary><b>🪟 Windows</b></summary>

Открой **cmd** (Win+R → `cmd` → Enter, или в терминале VS Code стрелка у `+` → Command
Prompt). PowerShell не используй: он блокирует часть команд.

Для файла `mklink`, для папки `mklink /D`:

```cmd
mklink "%USERPROFILE%\.claude\CLAUDE.md" "%USERPROFILE%\work\claude-config\CLAUDE.md"
mklink /D "%USERPROFILE%\.claude\rules" "%USERPROFILE%\work\claude-config\rules"
```

Если папки `rules` (или `skills`, `commands`, `agents`) ещё нет, сначала создай её:

```cmd
mkdir "%USERPROFILE%\work\claude-config\rules"
```

**Ошибка про права?** Нужен **Режим разработчика**: без него Windows не даёт обычному
пользователю создавать ссылки. Win+R → `ms-settings:developers` → Enter → включи
**«Режим разработчика»**. Не открылось: Параметры → поиск «Для разработчиков».

⚠️ **После включения перезапусти VS Code** (иногда нужен и перезаход в систему): права
выдаются программе при запуске, уже открытое окно про них не узнает.

Не помогло: запусти cmd от имени администратора (правой кнопкой → «Запуск от имени
администратора») и повтори.

</details>

<details>
<summary><b>🍎 macOS / 🐧 Linux</b></summary>

```bash
mkdir -p ~/work/claude-config/rules
ln -s ~/work/claude-config/CLAUDE.md ~/.claude/CLAUDE.md
ln -s ~/work/claude-config/rules ~/.claude/rules
```

Повтори для `settings.json`, `skills`, `commands`, `agents`. Принцип один:
`ln -s <куда переехало> <где было>`.

⚠️ Если `~/.claude/rules` уже существует как обычная папка, `ln -s` её не заменит. Сначала
перенеси содержимое в `claude-config`, удали пустой оригинал, потом создай ссылку.

Проверка (ссылки видно по стрелке `->`):

```bash
ls -la ~/.claude
```

</details>
